# Git ブランチ運用ルール（このプロジェクト専用・グローバルルールより優先）

グローバルルール（ユーザースコープ CLAUDE.md）の「ソロ開発なので main 直接コミット可」は
**このプロジェクトには適用しない**。本プロジェクトは以下の運用とする。

## ブランチ戦略

1. **main に直接コミットしない。** 実装機能・バグ修正・ドキュメント整備ごとにブランチを切る。
2. ブランチ名は既存慣習に従う:
   - `feature/<機能名>` … 機能実装（例: feature/user-block）
   - `fix/<修正内容>` … バグ修正（例: fix/keyboard-dismiss）
   - `refactor/<内容>` … リファクタリング・UI刷新
   - `docs/<内容>` … ドキュメント整備
3. 作業完了後、push して **PR を作成し、ユーザーがレビュー・マージする**（Claude が自分でマージしない）。
4. commit / push はユーザーの指示があるときのみ（グローバルルールと同じ）。
5. コミットは小さく・意味の分かる単位で。メッセージは既存慣習（日本語、`feature(scope): 内容` / `fix:` / `chore:` / `docs:` 形式）に従う。

## 注意事項

- 新ブランチは原則 **最新の main** から切る。
- マージ済みブランチはユーザー確認のうえ削除してよい（勝手に削除しない）。
- ストア申請時は提出コミットに `vX.Y.Z` タグ必須（グローバルルール。現状未運用なので今後徹底）。
